Eine Testumgebung verwenden

Um mehrere Installationen von darktable auf deinem Computer auszuführen, beispielsweise um einen Nightly-Build auszuprobieren, kannst du jeder Installation eine eigene Konfiguration zuweisen, ohne dass dies Auswirkungen auf die anderen hat.

Dazu sind drei Schritte notwendig:

  1. Installiere die zusätzliche darktable-Version ohne die existierende Installation zu überschreiben.

  2. weise der neuen Installation ihr eigenes Konfigurationsverzeichnis zu.

  3. stelle sicher, dass die neue Installation bestehende Bearbeitungen nicht verändert.

Hinweis: Es kann passieren, dass durch Fehler beim Aufsetzen der Testinstallation die Hauptinstallation verändert wird. Vor dem Start sollte deshalb eine Sicherung des Konfigurationsverzeichnisses angelegt werden. Möglicherweise ist eine regelmäßige Sicherung des Konfigurationsverzeichnisses sinnvoll.

🔗1. Installiere die gewünschte Testversion

Linux Die einfachste Option ist die Installation eines AppImage, falls verfügbar. Dieses muss nur heruntergeladen und die Ausführung der Datei erlaubt werden. Alternativ kannst Du darktable auch selbst aus dem Quelltext erzeugen und mit einem eigenen Präfix installieren (zum Beispiel mit der Option --prefix /opt/darktable-nightly).

Windows
Installiere die Testversion in ein separates Verzeichnis
macOS
Benenne die .app-Datei um (zum Beispiel in darktable-nightly.app) bevor du sie nach /Aplicationsverschiebst, um die existierende Datei nicht zu überschreiben.

🔗2. Ein separates Konfigurationsverzeichnis aufsetzen

Darktable speichert Einstellungen, Voreinstellungen, Stile und die Bibliotheks-Datenbank in einem Konfigurationsverzeichnis. Der Standardablageort dieses Verzeichnisses hängt vom Betriebssystem und der verwendeten Installationsmethode ab.

Um zu verhindern, dass eine Installation dasselbe Konfigurationsverzeichnis wie eine andere Installation verwendet, starte das Programm mit der Option --configdirgefolgt vom Pfad des neuen Verzeichnisses. Falls dieses noch nicht existiert, wird es von darktable automatisch angelegt und verwendet.

Wenn du mit der neuen Version experimentierst kannst du dauerhafte Änderungen an der Bibliothek mit der Option --library :memory:vermeiden. Die Bibliothek wird dann nur im Hauptspeicher gehalten und alle Änderungen an der Datenbank beim Programmende verworfen: darktable --configdir /path/to/test-config --library :memory:

Tipp Anstatt ganz von vorne zu beginnen, kannst du auch ein existierendes Konfigurationsverzeichnis in das neue Verzeichnis kopieren. Damit werden die existierenden Voreinstellungen, Stile und Kurzbefehle übernommen, während beide Installationen weiterhin unabhängig voneinander sind. Wenn du Konfigurationen selektiver übernehmen möchtest, genügen für den Anfang die Dateien darktablerc, shortcutsrcund data.db, das Styles-Verzeichnis und möglicherweise das Lua-Verzeichnis und die Datei luarc(falls vorhanden). Wenn du das komplette Verzeichnis kopierst, insbesonderen wenn die Datei library.dbmit kopiert wird, achte in Schritt 3 darauf, dass bestehende Bearbeitungen nicht geändert werden.

Linux
Füjhre die folgenden Befehle in einem Kommandozeilenfenster aus:.
  • Appimage: Pfad-der-Appimage-Datei/darktable.Appimage --configdir /Pfad-des-Test-Konfigurationsverzeichnisses
  • selbst erzeugte Binärdatei: Pfad-der-Binärdatei/darktable --configdir /Pfad-des-Test-Konfigurationsverzeichnisses

Um den Aufruf zu vereinfachen, kannst Du den Befehl in ein Shellskript oder eine .desktop-Datei schreiben (siehe darktables .desktop-Datei als Beispiel).

Windows
lege eine neue Verknüpfung für darktable.exean:
  1. Navigiere zu C:\Installationsverzeichnis\bin\, klicke mit der rechten Maustaste auf darktable.exeund wähle mehr Optionen und dann Verknüpfung anlegen.
  2. In den Eigenschaften der Verknüpfung füge im Feld “Ziel” die Option --configdirhinzu: "C:\Installationspfad\bin\darktable.exe" --configdir "C:\Pfad-des-Test-Konfigurationsverzeichnisses"
  3. Setze “Startet in” auf das entsprechende bin-Verzeichnis.

Alternativ: Starte darktable in einem Kommandozeilenfenster.

cd "C:\Installationspfad\bin\"
.\darktable.exe --configdir "C:\Pfad-des-Test-Konfigurationsverzeichnisses"
macOS
eine .app-Datei kann durch Doppelklick nicht mit zusätzlichen Parametern gestartet werden. Starte die ausführbare Datei im App-Bundle direkt in einem Terminalfenster. 
/Applications/darktable-nightly.app/Contents/MacOS/darktable --configdir /Pfad/zum/neuen/Konfigurationsverzeichnis

Ersetze darktable-nightly.appdurch den Dateinamen der .app-Datei für die Testversion.

🔗3. Schütze existierende Bearbeitungen

Die Bearbeitungsschritte eines Bildes werden an zwei Stellen gespeichert: In der Bibliotheksdatenbank im Konfigurationsverzeichnis und in XMP-Begleitdateien, sofern dies in den Einstellungen aktiviert wurde. In Schritt 2 wurde der Testinstallation eine neue Bibliotheksdatenbank zugeordnet, allerdings werden die XMP-Begleitdateien zusammen mit den RAW-Dateien abgelegt und somit von beiden Installationen verwendet.

Um zu Verhindern, dass die andere Installation bestehende XMP-Dateien verändert, hat der Anwender zwei Optionen:

a) Verwendung von separaten Kopien der RAW Dateien
Die sicherste Option. Verwende bei Nutzung einer anderen Version von darktable Kopien deiner RAW-Dateien in einem eigenen Ordner: Die original RAW-Dateien und deren XMP Begleitdateien bleiben unverändert.
b) Deaktiviere die Verwendung von XMP in der anderen Installation
Starte darktable mit der Option --conf write_sidecar_files=never. Alternativ kann die Voreinstellung Eigenschaften / Speichern / XMP-Dateien erzeugen’ auf nie gesetzt werden. Damit können Verzeichnisse mit existierenden Bearbeitungen ohne Veränderungen der XMP-Dateien geöffnet werden. Diese Einstellung beeinflusst nur die eigene Installation, weil jede Installation ihre eigene Konfiguration hat.

Achtung Falls du ein existierendes Konfigurationsverzeichnis für die Testinstallation kopiert hast, solltest Du die Erzeugung von XMP-Dateien wie in Schritt 3b beschrieben deaktivieren. Alternativ kannst Du alle Bilder aus der neuen Installation entfernen (nicht löschen). Dies entfernt die Bilder nur aus der Bibliotheksdatenbank, löscht sie aber nicht von der Festplatte. Andernfalls könnten Bearbeitungen, die mit der Originalinstallation gemacht wurden, verändert werden.

🔗Zusammenfassung

Für eine unabhängige Installation die keine XMP-Begleitdateien schreibt:

Linux/macOS
Optionen 
--configdir /Pfad-zum-Test-Konfigurationsverzeichnis --conf write_sidecar_files=never
Windows
Optionen 
--configdir "C:\Pfad-zum-Test-Konfigurationsverzeichnis" --conf "write_sidecar_files=never"
Linux/macOS
Optionen 
--configdir /Pfad-zum-Test-Konfigurationsverzeichnis --conf write_sidecar_files=never --library :memory:
Windows
Optionen 
--configdir "C:\Pfad-zum-Test-Konfigurationsverzeichnis" --conf "write_sidecar_files=never" --library ":memory:"

Am sichersten ist es, Kopien der RAW-Dateien zu verwenden, anstatt nur die Erzeugung von XMP-Dateien zu deaktivieren.
