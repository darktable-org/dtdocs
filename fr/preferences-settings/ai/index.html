Préférences et réglages/IA

IA

Table des matières
  • Général
  • installation d’un Runtime ONNX GPU
  • Modèles

Contrôlez les fonctionnalités IA de Darktable : activez-les ou désactivez-les, choisissez un accélérateur matériel pour l’inférence de modèle, faites pointer darktable sur une bibliothèque ONNX Runtime et gérez les modèles d’IA disponibles sur le disque.

Les fonctionnalités d’IA sont alimentées par ONNX Runtime. Ce qui est prêt à l’emploi et l’accélération GPU peuvent être ajoutés sur chaque plate-forme :

OS Lié Accélération GPU optionnelle
Linux CPU seul NVIDIA CUDA, AMD ROCm/MIGraphX, Intel OpenVINO
Windows DirectML (n’import quel GPU DirectX 12) NVIDIA CUDA, Intel OpenVINO
macOS CoreML (Apple Silicon, GPU integré) –

Les scripts d’installation pour les environnements d’exécution du GPU sont décrits ci-dessous ; voir Accélération GPU pour les instructions complètes.

Pour une explication plus approfondie du fonctionnement des fonctionnalités IA – l’exécution de l’inférence, les fournisseurs d’exécution, la disposition du modèle, l’accélération GPU et le dépannage –, consultez la rubrique spéciale Fonctionnalités IA.

#Général

Activer les fonctionnalités IA
Commutateur principal pour toutes les fonctionnalités IA. Lorsqu’il est désactivé, aucun Runtime ONNX n’est chargé, aucun répertoire de modèle n’est analysé et les modules dépendants de l’IA se cachent. Désactivez cette option pour éliminer la mémoire liée à l’IA et les coûts de démarrage lorsque vous n’en avez pas besoin (désactivé par défaut).
Accélération de l’IA
L’accélérateur matériel utilisé pour l’inférence du modèle. La liste affiche uniquement les fournisseurs actuellement disponibles tels que pris en charge par ONNX Runtime chargé. L’installation d’un ONNX Runtime différent met à jour la liste.
  • auto choisit le meilleur fournisseur disponible pour la bibliothèque chargée, revenant au processeur si aucun accélérateur ne s’initialise.
  • CPU exécute l’inférence sur le processeur. Toujours disponible.
  • NVIDIA CUDA utilise les GPU NVIDIA via cuDNN (Linux, Windows ; nécessite l’installation d’un ONNX Runtime compatible CUDA).
  • AMD MIGraphX utilise les GPU AMD via ROCm (Linux uniquement ; nécessite l’installation d’un ONNX Runtime compatible MIGraphX).
  • Intel OpenVINO utilise des GPU Intel et des iGPU via OpenVINO (Linux, Windows ; nécessite l’installation d’un ONNX Runtime compatible OpenVINO).
  • Windows DirectML utilise n’importe quel GPU compatible DirectX 12 (Windows ; fourni par défaut).
  • Apple CoreML utilise l’Apple Neural Engine et le GPU intégré (macOS ; fourni par défaut).

Double-cliquez sur l’étiquette pour revenir à la valeur par défaut. Si le fournisseur sélectionné ne peut pas être initialisé avec le runtime ONNX actuellement chargé (par exemple, si la bibliothèque a été créée sans ce fournisseur), un avis non disponible retournera au CPU apparaît à côté de la zone de liste déroulante. Après avoir échangé la bibliothèque ONNX Runtime, l’avis devient redémarrer pour appliquer jusqu’à ce que Darktable soit redémarré.

Bibliothèque ONNX Runtime
Chemin vers une bibliothèque partagée (libonnxruntime.so* sous Linux, onnxruntime.dll sous Windows) que Darktable doit charger à la place de celle fournie. Laissez vide pour utiliser la bibliothèque fournie (voir le tableau ci-dessus pour savoir ce que cela comprend par système d’exploitation). Pour utiliser un runtime GPU, installez-en un via les scripts décrits ci-dessous et pointez ce champ vers celui-ci. Double-cliquez sur l’étiquette pour la réinitialiser à vide. Les modifications prennent effet après le redémarrage de Darktable. Caché sur macOS, où ONNX Runtime est lié statiquement au support CoreML.

À la droite du champ de chemin se trouvent deux boutons :

  • Parcourir (icône de dossier) – ouvrez un explorateur de fichiers pour choisir une bibliothèque ONNX Runtime personnalisée. La sélection est validée en chargeant la bibliothèque et en sondant sa version et les fournisseurs d’exécution disponibles ; si le fichier n’est pas une version de ONNX Runtime valide, il est rejeté et le chemin précédent est restauré.
  • Détecter – analyse les emplacements système standard pour une bibliothèque ONNX Runtime (installation par le gestionnaire de paquet, /usr/lib, /usr/local/lib, ~/.local/lib). Si plusieurs candidats sont trouvés, il vous sera demandé de choisir ; si un seul est trouvé, il est appliqué automatiquement. Utile lorsque vous avez installé ONNX Runtime via le gestionnaire de paquets de votre distribution ou via le script d’installation décrit ci-dessous.

#installation d’un Runtime ONNX GPU

L’accélération GPU sous Linux et Windows (NVIDIA CUDA, AMD MIGraphX, Intel OpenVINO) nécessite une version ONNX Runtime compatible GPU, que Darktable ne livre pas dans l’application. Les scripts d’installation gèrent cela de bout en bout – détection de votre GPU, téléchargement du runtime correspondant, vérification de celui-ci et installation sous votre compte utilisateur.

Voir Accélération GPU pour les instructions complètes : installateurs en une seule ligne pour Linux et Windows, prérequis, exigences GPU et pilotes, installation manuelle alternative, création d’AMD ONNX Runtime à partir de la source et dépannage.

Après l’installation, redémarrez Darktable, puis utilisez le bouton détection ci-dessus pour pointer Darktable vers la bibliothèque nouvellement installée (ou sélectionnez le fichier manuellement avec le bouton Parcourir).

#Modèles

La moitié inférieure de l’onglet répertorie les modèles d’IA connus de Darktable – à la fois ceux déjà téléchargés et ceux disponibles dans le référentiel de modèles darktable-ia.

Liste de modèles
Tous les modules utilitaires ont les éléments suivants :
  • sélection (case à cocher la plus à gauche) – inclure le modèle dans les opérations en masse (télécharger / mettre à jour la sélection, supprimer les sélectionnés). Indépendent de l’état activé. La case à cocher d’en-tête bascule toutes les lignes à la fois.
  • nom – nom du modèle.
  • bouton info (icône i) – cliquez pour ouvrir la carte modèle avec les métadonnées complètes : périmètre, auteur, source, papier, licence, données d’entraînement, licence des données, notes.
  • version – version du modèle à partir du manifeste du référentiel.
  • tâche – à quelle tâche ce modèle sert : mask, denoise, rawdenoise, upscale.
  • activé – marque le modèle comme actif pour sa tâche. Un seul modèle peut être actif par tâche à la fois : cocher la case sur un deuxième modèle de la même tâche décoche automatiquement celui précédemment actif, comme un bouton radio. Décocher le modèle actif laisse la tâche sans modèle actif jusqu’à ce qu’un autre soit sélectionné. Les modules dépendants de l’IA utilisent le modèle actuellement actif pour leur tâche.
  • état – téléchargé, pas téléchargé, mise à jour disponible ou mise à jour requise.
  • défaut – oui si le modèle est recommandé par défaut par le développeur (sélectionné par télécharger / mettre à jour les défauts), non sinon.
Télécharger / mettre à jour des valeurs par défaut
Téléchargez ou mettez à jour le sous-ensemble de modèles que les développeurs de Darktable recommandent comme valeurs par défaut pour chaque tâche. Utile pour démarrer rapidement avec une nouvelle installation et pour intégrer toutes les versions plus récentes de ces modèles que le référentiel a publiées depuis.
Télécharger / mettre à jour la sélection
Téléchargez ou mettez à jour les modèles dont la case à cocher selectionné est cochée. Utilisez ceci lorsque vous avez coché un ou quelques modèles spécifiques dans la liste et que vous souhaitez uniquement opérer sur ceux-ci.
Importer depuis un fichier…
Installez un modèle à partir d’une archive locale .dtmodel. L’explorateur de fichiers filtre par *.dtmodel ; une fois importé, le modèle devient immédiatement disponible. Utilisez ceci pour les modèles qui vous ont été donnés directement, les modèles que vous avez construits vous-même, ou des d’autres alternatives par tâche à partir du dépôt darktable-ia – la liste intégrée à l’application n’affiche qu’un ou deux modèles par tâche, mais le référentiel peut publier d’autres alternatives pour la même tâche (modèle de débruitage différent formé sur un ensemble de données différent, dorsale de segmentation alternative, etc.). Téléchargez le .dtmodel à partir des versions GitHub du référentiel et importez-le ici.
Supprimer la sélection
Supprimez les modèles dont la case à cocher selectionné est cochée du disque. Les modèles fournis avec Darktable ne peuvent pas être supprimés.

Les téléchargements s’exécutent en arrière-plan avec une boîte de dialogue de progression et peuvent être annulés. Les téléchargements échoués sont signalés et les modèles concernés restent dans leur état précédent.
