darktable-cli

ໄຟລ໌ລັນ darktable-cli ເລີ່ມຕົ້ນ darktable ໃນຮູບແບບສ່ວນຕິດຕໍ່ຜ່ານຄຳສັ່ງ (command line interface) ເຊິ່ງຊ່ວຍໃຫ້ສາມາດສົ່ງອອກຮູບພາບໄດ້.

ຮູບແບບນີ້ຈະບໍ່ເປີດການສະແດງຜົນໃດໆ – ມັນເຮັດວຽກໃນໂໝດຄອນໂຊລລ້ວນໆ ໂດຍບໍ່ມີການເປີດ GUI. ໂໝດນີ້ມີປະໂຫຍດຫຼາຍສຳລັບເຊີບເວີທີ່ລັນວຽກເບື້ອງຫຼັງ.

darktable-cli ສາມາດເອີ້ນໃຊ້ໄດ້ດ້ວຍພານາມິເຕີຄຳສັ່ງດັ່ງຕໍ່ໄປນີ້:

darktable-cli [<input file or folder>]
              [<xmp file>]
              <output file or folder>
              [--width <max width>]
              [--height <max height>]
              [--hq <0|1|true|false>]
              [--upscale <0|1|true|false>]
              [--style <style name>]
              [--style-overwrite]
              [--apply-custom-presets <0|1|false|true>]
              [--out-ext <extension>]
              [--import <file or dir>]
              [--library <path>]
              [--icc-type <type>]
              [--icc-file <file>]
              [--icc-intent <intent>]
              [--print-paths]
              [--print-paths-as-flags]
              [--verbose]
              [--help [option]]
              [--core <darktable options>]

ຜູ້ໃຊ້ຕ້ອງລະບຸຊື່ໄຟລ໌ຂາເຂົ້າ ແລະ ຊື່ໄຟລ໌ຂາອອກ. ພານາມິເຕີອື່ນໆທັງໝົດແມ່ນເປັນທາງເລືອກ.

<input file or folder>
ຊື່ຂອງໄຟລ໌ ຫຼື ໂຟນເດີຂາເຂົ້າ (ທີ່ບັນຈຸຮູບພາບ) ທີ່ຈະສົ່ງອອກ. ຖ້າທ່ານຕ້ອງການປະມວນຜົນຫຼາຍຮູບພາບ ຫຼື ຫຼາຍໂຟນເດີ ໃຫ້ໃຊ້ຕົວເລືອກ --import ແທນ.
<xmp file>
ຊື່ໄຟລ໌ XMP (ເປັນທາງເລືອກ) ທີ່ບັນຈຸຂໍ້ມູນລາຍການປະຫວັດທີ່ຈະນຳໃຊ້ໃນລະຫວ່າງການສົ່ງອອກ. ຖ້າບໍ່ໄດ້ລະບຸຕົວເລືອກນີ້ darktable ຈະຄົ້ນຫາໄຟລ໌ XMP ທີ່ເປັນຂອງໄຟລ໌ຂາເຂົ້າທີ່ກຳນົດ.
<output file or folder>
ຊື່ຂອງໄຟລ໌ຂາອອກ ຫຼື ໂຟນເດີປາຍທາງ. ພານາມິເຕີນີ້ແມ່ນຈໍາເປັນຖ້າທ່ານໃຊ້ໂປຣແກຣມກັບໂຟນເດີຮູບພາບທີ່ບັນຈຸຫຼາຍຮູບພາບ, ແລະ ມັນຕ້ອງຊີ້ໄປຫາໂຟນເດີທີ່ມີຢູ່ແລ້ວ. ຖ້າເສັ້ນທາງທີ່ລະບຸບໍ່ໄດ້ຊີ້ໄປຫາໂຟນເດີທີ່ມີຢູ່, ມັນຈະຖືກຕີຄວາມໝາຍວ່າເປັນຊື່ໄຟລ໌. ຖ້າເສັ້ນທາງຖືກຕີຄວາມໝາຍວ່າເປັນຊື່ໄຟລ໌, ຮູບແບບໄຟລ໌ສົ່ງອອກຈະຖືກກຳນົດຈາກນາມສະກຸນໄຟລ໌, ນອກຈາກວ່າຈະມີຕົວເລືອກ --out-ext (ເບິ່ງຂ້າງລຸ່ມ). ໝາຍເຫດວ່ານາມສະກຸນໄຟລ໌ແມ່ນໃຊ້ເພື່ອລະບຸ ຮູບແບບການສົ່ງອອກ (export format) ເທົ່ານັ້ນ, ເຊິ່ງຈາກນັ້ນຈະບັງຄັບໃຊ້ນາມສະກຸນຂາອອກຕົວຈິງ (ເຊັ່ນ: image.jpeg ຈະຕັ້ງຮູບແບບເປັນ JPEG, ເຊິ່ງສົ່ງຜົນໃຫ້ໄດ້ຊື່ໄຟລ໌ image.jpg). ທ່ານຍັງສາມາດໃຊ້ ຕົວປ່ຽນ (variables) ຫຼາຍຢ່າງໃນຊື່ໄຟລ໌ຂາອອກ. ຖ້າທ່ານລະບຸໂຟນເດີຂາອອກ ແນະນຳໃຫ້ທ່ານລະບຸຮູບແບບໄຟລ໌ດ້ວຍ --out-ext ນຳ.
--width <max width>
ຈຳກັດຄວາມກວ້າງຂອງຮູບພາບທີ່ສົ່ງອອກຕາມຈຳນວນພິກເຊລທີ່ກຳນົດ.
--height <max height>
ຈຳກັດຄວາມສູງຂອງຮູບພາບທີ່ສົ່ງອອກຕາມຈຳນວນພິກເຊລທີ່ກຳນົດ.
--hq <0|1|true|false>
ກຳນົດວ່າຈະໃຊ້ການສຸ່ມຕົວຢ່າງໃໝ່ຄຸນນະພາບສູງໃນລະຫວ່າງການສົ່ງອອກຫຼືບໍ່ (ເບິ່ງລາຍລະອຽດເພີ່ມເຕີມໃນໂມດູນ ການສົ່ງອອກ). ຄ່າເລີ່ມຕົ້ນແມ່ນ true.
--upscale <0|1|true|false>
ກຳນົດວ່າຈະອະນຸຍາດໃຫ້ຂະຫຍາຍຂະໜາດ (upscaling) ໃນລະຫວ່າງການສົ່ງອອກຫຼືບໍ່. ຄ່າເລີ່ມຕົ້ນແມ່ນ false.
--style <style name>
ລະບຸຊື່ຂອງສະໄຕລ໌ທີ່ຈະນຳໃຊ້ໃນລະຫວ່າງການສົ່ງອອກ. ຖ້າລະບຸສະໄຕລ໌, ຕ້ອງລະບຸເສັ້ນທາງໄປຫາໂຟນເດີກຳນົດຄ່າຂອງ darktable ນຳ (ເຊັ່ນ: --core --configdir ~/.config/darktable). ໂດຍເລີ່ມຕົ້ນຈະບໍ່ມີການນຳໃຊ້ສະໄຕລ໌.
--style-overwrite
ສະໄຕລ໌ທີ່ລະບຸຈະຂຽນທັບລາຍການປະຫວັດ ແທນທີ່ຈະເປັນການຕໍ່ທ້າຍ.
--apply-custom-presets <0|1|false|true>
ກຳນົດວ່າຈະໂຫຼດ data.db ເຊິ່ງບັນຈຸຄ່າທີ່ຕັ້ງໄວ້ກ່ອນ ແລະ ສະໄຕລ໌ຫຼືບໍ່. ການປິດຕົວເລືອກນີ້ຊ່ວຍໃຫ້ທ່ານສາມາດລັນ darktable-cli ໄດ້ຫຼາຍຕົວພ້ອມກັນ ແຕ່ຈະບໍ່ສາມາດໃຊ້ຕົວເລືອກ --style ໄດ້. ຄ່າເລີ່ມຕົ້ນແມ່ນ true.
--out-ext <extension>
ກຳນົດຮູບແບບການສົ່ງອອກທີ່ຈະໃຊ້ (ເຊັ່ນ: jpeg, tiff, openexr) ໂດຍອີງຕາມຂໍ້ຄວາມທີ່ໃຫ້ມາ, ເຊິ່ງອາດຈະເປັນນາມສະກຸນທົ່ວໄປ (ເຊັ່ນ: jpg, tif, exr) ຫຼື ຮູບແບບ (ເຊັ່ນ: jpeg, tiff). ຊື່ --out-ext ຖືກຮັກສາໄວ້ເພື່ອຄວາມເຂົ້າກັນໄດ້ກັບສະຄຣິບທີ່ມີຢູ່, ແຕ່ໃນຄວາມເປັນຈິງແລ້ວມັນຖືກໃຊ້ເພື່ອລະບຸ ຮູບແບບ (format), ບໍ່ແມ່ນນາມສະກຸນໄຟລ໌; ສ່ວນນາມສະກຸນນັ້ນ ປົກກະຕິແລ້ວຈະຖືກກຳນົດໂດຍຮູບແບບເອງ. ຖ້າລະບຸ, ຮູບແບບນີ້ຈະມີຄວາມສຳຄັນສູງກວ່າຮູບແບບທີ່ໄດ້ມາຈາກ <output file>. ຖ້າຊື່ໄຟລ໌ຂາອອກມີນາມສະກຸນຢູ່ແລ້ວ, ມັນຈະຖືກລຶບອອກ ກໍຕໍ່ເມື່ອ ມັນກົງກັບຂໍ້ຄວາມທີ່ສົ່ງໃຫ້ --out-ext ຢ່າງແນ່ນອນ. ຖ້າບໍ່ດັ່ງນັ້ນ, ມັນຈະຖືກຖືວ່າເປັນສ່ວນໜຶ່ງຂອງຊື່ໄຟລ໌ (ເຊັ່ນ: output.jpg ທີ່ມີ --out-ext jpeg ຈະສົ່ງຜົນໃຫ້ໄດ້ output.jpg.jpg, ເພາະວ່າ jpg ບໍ່ກົງກັບ jpeg). ຄ່າເລີ່ມຕົ້ນແມ່ນ jpg ຖ້າລະບຸ <output folder>.
--import <file or dir>
ລະບຸໄຟລ໌ ຫຼື ໂຟນເດີຂາເຂົ້າ, ສາມາດໃຊ້ໄດ້ຫຼາຍຄັ້ງ. ຕົວເລືອກນີ້ບໍ່ສາມາດໃຊ້ຮ່ວມກັບ <input file or folder> ໄດ້.
--library <path>
ອ່ານປະຫວັດການປະມວນຜົນຮູບພາບຈາກຖານຂໍ້ມູນທີ່ລະບຸ ແທນທີ່ຈະເປັນໄຟລ໌ sidecar XMP.
--icc-type <type>
ລະບຸປະເພດໂປຣໄຟລ໌ ICC, ເຊິ່ງຄືກັນກັບການລະບຸ “output profile” ໃນໂມດູນ output color profile. ຄ່າເລີ່ມຕົ້ນແມ່ນ “image specified”. ໃຊ້ --help icc-type ເພື່ອເບິ່ງລາຍການປະເພດທີ່ຮອງຮັບ. ເບິ່ງລາຍລະອຽດເພີ່ມເຕີມໃນຄູ່ມືການໃຊ້ໂມດູນ output color profile.
--icc-file <file>
ລະບຸຊື່ໄຟລ໌ໂປຣໄຟລ໌ ICC. ຄ່າເລີ່ມຕົ້ນແມ່ນຊື່ໄຟລ໌ຫວ່າງເປົ່າ.
--icc-intent <intent>
ລະບຸຈຸດປະສົງການສະແດງຜົນ (rendering intent). ຄ່າເລີ່ມຕົ້ນແມ່ນ “image specified”. ໃຊ້ --help icc-intent ເພື່ອເບິ່ງລາຍການທີ່ຮອງຮັບ. ເບິ່ງ rendering intent ສຳລັບລາຍລະອຽດເພີ່ມເຕີມ.
--print-paths
Print the resolved configdir, cachedir, tmpdir, datadir, moduledir, localedir and library paths for this install, honoring any of the overrides, then exit.
--print-paths-as-flags
Like --print-paths, but printed as a single line of –flag value pairs ready to insert into another invocation’s command line (for darktable-cli they need to be after the --core flag).
--verbose
ເປີດການສະແດງຜົນລາຍລະອຽດ.
--help [option]
ສະແດງວິທີການໃຊ້ງານ ແລະ ອອກຈາກໂປຣແກຣມ. ຖ້າລະບຸ option, ຈະສະແດງວິທີການໃຊ້ງານສຳລັບຕົວເລືອກນັ້ນຕື່ມ.
--core <darktable options>
ພາລາມິເຕີທັງໝົດທີ່ຢູ່ຫຼັງ --core ຈະຖືກສົ່ງໄປຫາພາກສ່ວນຫຼັກ (core) ຂອງ darktable ແລະ ຖືກຈັດການເປັນພາລາມິເຕີມາດຕະຖານ. ເບິ່ງລາຍລະອຽດໃນພາກ darktable binary.

🔗ຕົວເລືອກການສົ່ງອອກ

ຕົວເລືອກການສົ່ງອອກສຳລັບ darktable ແມ່ນຖືກກຳນົດເປັນລາຍການການຕັ້ງຄ່າ, ຕັ້ງຄ່າຈາກພາຍໃນ ໂມດູນການສົ່ງອອກ. ມີສອງວິທີໃນການປ່ຽນແປງການຕັ້ງຄ່ານີ້ເມື່ອໃຊ້ darktable-cli ຕາມທີ່ອະທິບາຍໄວ້ລຸ່ມນີ້.

🔗ໃຊ້ໂມດູນການສົ່ງອອກ

ຄຳສັ່ງ darktable-cli ຈະໃຊ້ຮູບແບບການກຳນົດຄ່າລ້າສຸດທີ່ໃຊ້ໃນໂມດູນການສົ່ງອອກ ເມື່ອລັນໃນໂໝດໂຕ້ຕອບ (gui). ດັ່ງນັ້ນ, ເຈົ້າສາມາດຕັ້ງຄ່າຕົວເລືອກຮູບແບບທີ່ເຈົ້າຕ້ອງການດ້ວຍຕົນເອງໃນ darktable gui ແລ້ວຈຶ່ງລັນ darktable-cli ເພື່ອສົ່ງອອກໄຟລ໌ຂອງເຈົ້າ.

🔗ສົ່ງຕົວເລືອກຜ່ານສາຍຄຳສັ່ງ

ທ່ານສາມາດຕັ້ງຄ່າຕົວເລືອກການສົ່ງອອກໃດໆກໍໄດ້ໂດຍໃຊ້ຮູບແບບຄຳສັ່ງດັ່ງນີ້:

    --core --conf plugins/imageio/format/<FORMAT>/<OPTION>=<VALUE>

ຕົວເລືອກທີ່ຕັ້ງຄ່າດ້ວຍວິທີນີ້ຈະບໍ່ຖືກເກັບໄວ້ຖາວອນ ແຕ່ຈະຖືກໃຊ້ສະເພາະການເຮັດວຽກຂອງ darktable-cli ໃນຄັ້ງນີ້ເທົ່ານັ້ນ.
