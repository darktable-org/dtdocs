      darktable

      ໄຟລ໌ໄບນາຣີ darktable ຈະເລີ່ມຕົ້ນ darktable ດ້ວຍ GUI ແລະ ຟັງຊັນການເຮັດວຽກທີ່ຄົບຖ້ວນ. ນີ້ແມ່ນວິທີມາດຕະຖານໃນການໃຊ້ darktable. ຄຳສັ່ງໃນການລັນໄຟລ໌ໄບນາຣີ ຂຶ້ນກັບລະບົບປະຕິບັດການຂອງທ່ານ.

      ມີພາລາມິເຕີສາຍຄຳສັ່ງດັ່ງນີ້:

      darktable [-d {all,act_on,ai,cache,camctl,camsupport,common,control,
               dev,expose,fswatch,imageio,input,ioporder,lighttable,lua,
               masks,memory,nan,opencl,params,perf,pipe,print,pwstorage,
               signal,sql,tiling,undo,verbose}]
          [--d-signal <signal>]
          [--d-signal-act <all,raise,connect,disconnect,print-trace>]
          [--disable-pipecache]
          [<input file>|<image folder>]
          [--version]
          [--disable-opencl]
          [--configdir <user config directory>]
          [--library <library file>]
          [--datadir <data directory>]
          [--moduledir <module directory>]
          [--tmpdir <tmp directory>]
          [--cachedir <user cache directory>]
          [--localedir <locale directory>]
          [--print-paths]
          [--print-paths-as-flags]
          [--luacmd <lua command>]
          [--noiseprofiles <noiseprofiles json file>]
          [--conf <key>=<value>]
          [-t <num openmp threads>]

      ພາລາມິເຕີທັງໝົດແມ່ນເປັນຕົວເລືອກ. ໃນກໍລະນີສ່ວນໃຫຍ່ darktable ຄວນຖືກເລີ່ມຕົ້ນໂດຍບໍ່ມີພາລາມິເຕີເພີ່ມເຕີມ, ເຊິ່ງໃນກໍລະນີນີ້ darktable ຈະໃຊ້ຄ່າເລີ່ມຕົ້ນທີ່ເໝາະສົມ.

      -d {all,act_on,ai,cache,camctl,camsupport,common,control,dev,expose,fswatch,imageio,input,ioporder,lighttable,lua,masks,memory,nan,opencl,params,perf,pipe,print,pwstorage,signal,sql,tiling,undo,verbose}
      ເປີດໃຊ້ການສະແດງຜົນການແກ້ໄຂຂໍ້ຜິດພາດ (debug) ໃນເທີມິນອລ (terminal). darktable ມີຫຼາຍລະບົບຍ່ອຍ ແລະ ແຕ່ລະລະບົບສາມາດແກ້ໄຂຂໍ້ຜິດພາດແຍກກັນໄດ້. ທ່ານສາມາດໃຊ້ຕົວເລືອກນີ້ຫຼາຍຄັ້ງຖ້າທ່ານຕ້ອງການແກ້ໄຂຂໍ້ຜິດພາດຫຼາຍກວ່າໜຶ່ງລະບົບຍ່ອຍ (ເຊັ່ນ darktable -d opencl -d camctl) ຫຼື ແກ້ໄຂຂໍ້ຜິດພາດທັງໝົດພ້ອມກັນ (ດ້ວຍ -d all). ຕົວເລືອກ -d common ມີໄວ້ເພື່ອໃຫ້ຂໍ້ມູນກ່ຽວກັບລະບົບຍ່ອຍທີ່ກ່ຽວຂ້ອງທີ່ສຸດໃນຂະນະທີ່ແກ້ໄຂຂໍ້ຜິດພາດ darktable ຫຼື ຖ້າທ່ານຕ້ອງການສົ່ງລັອກ (log) ເພື່ອລາຍງານບັນຫາ. ບາງຕົວເລືອກ (ເຊັ່ນ -d opencl) ສາມາດສະແດງລາຍລະອຽດເພີ່ມເຕີມໄດ້ໂດຍໃຊ້ຕົວເລືອກ -d verbose ຄວບຄູ່ໄປນຳ. ຕົວເລືອກ verbose ຕ້ອງຖືກລະບຸຢ່າງຊັດເຈນ ເຖິງແມ່ນວ່າຈະໃຊ້ -d all ກໍຕາມ.
      --d-signal <signal>
      ຖ້າລະບຸ -d signal ຫຼື -d all, ໃຫ້ໃຊ້ຕົວເລືອກນີ້ເພື່ອລະບຸສັນຍານ (signal) ທີ່ຈະແກ້ໄຂຂໍ້ຜິດພາດ. ລະບຸ ALL ເພື່ອແກ້ໄຂຂໍ້ຜິດພາດທຸກສັນຍານ ຫຼື ລະບຸຊື່ເຕັມຂອງສັນຍານ. ສາມາດໃຊ້ໄດ້ຫຼາຍຄັ້ງ.
      --d-signal-act <all,raise,connect,disconnect,print-trace>
      ຖ້າລະບຸ -d signal ຫຼື -d all, ໃຫ້ໃຊ້ຕົວເລືອກນີ້ເພື່ອລະບຸການກະທຳຂອງສັນຍານ (signal action) ທີ່ຈະແກ້ໄຂຂໍ້ຜິດພາດ.
      --disable-pipecache
      ປິດໃຊ້ງານແຄຊ໌ pixelpipe. ຕົວເລືອກນີ້ອະນຸຍາດໃຫ້ມີພຽງແຕ່ສອງ cachelines ຕໍ່ໜຶ່ງ pipe, ແລະ ຄວນໃຊ້ເພື່ອຈຸດປະສົງການແກ້ໄຂຂໍ້ຜິດພາດເທົ່ານັ້ນ.
      <input file>|<image folder>
      ລະບຸຊື່ໄຟລ໌ຮູບພາບ ຫຼື ໂຟນເດີ (ທາງເລືອກ). ຖ້າລະບຸຊື່ໄຟລ໌, darktable ຈະເລີ່ມຕົ້ນໃນມຸມມອງຫ້ອງມືດ (darkroom) ພ້ອມກັບເປີດໄຟລ໌ນັ້ນ. ຖ້າລະບຸໂຟນເດີ, darktable ຈະເລີ່ມຕົ້ນໃນມຸມມອງແຜງແສງ (lighttable) ໂດຍມີເນື້ອໃນໃນໂຟນເດີນັ້ນເປັນຄໍເລັກຊັນປັດຈຸບັນ.
      --version
      ສະແດງເລກເວີຊັນຂອງ darktable, ຂໍ້ມູນລິຂະສິດ, ແລະ ຂໍ້ມູນທີ່ມີປະໂຫຍດອື່ນໆ ແລ້ວຈົບການເຮັດວຽກ.
      --disable-opencl
      ປ້ອງກັນບໍ່ໃຫ້ darktable ເລີ່ມຕົ້ນລະບົບຍ່ອຍ OpenCL. ໃຊ້ຕົວເລືອກນີ້ຖ້າ darktable ຄ້າງ ຫຼື ດັບໃນຂະນະເລີ່ມຕົ້ນ ເນື່ອງຈາກການເຮັດວຽກຂອງ OpenCL ມີບັນຫາ.
      --configdir <config directory>
      ກຳນົດໂຟນເດີທີ່ darktable ໃຊ້ເກັບການຕັ້ງຄ່າສະເພາະຂອງຜູ້ໃຊ້. ເສັ້ນທາງເລີ່ມຕົ້ນແມ່ນມີລາຍຊື່ຢູ່ໃນໜ້າ configuration directory.
      --library <library file>
      darktable ເກັບຂໍ້ມູນຮູບພາບໄວ້ໃນຖານຂໍ້ມູນ sqlite ເພື່ອການເຂົ້າເຖິງທີ່ໄວ. ບ່ອນເກັບໄຟລ໌ຖານຂໍ້ມູນເລີ່ມຕົ້ນແມ່ນ library.db ໃນໂຟນເດີທີ່ລະບຸໂດຍ --configdir ຫຼື ໂຟນເດີການຕັ້ງຄ່າເລີ່ມຕົ້ນ. ໃຊ້ຕົວເລືອກນີ້ເພື່ອລະບຸບ່ອນເກັບອື່ນ (ເຊັ່ນ ຖ້າທ່ານຕ້ອງການທົດລອງບາງຢ່າງໂດຍບໍ່ໃຫ້ກະທົບກັບໄຟລ໌ library.db ຕົ້ນສະບັບ). ຖ້າບໍ່ມີໄຟລ໌ຖານຂໍ້ມູນຢູ່, darktable ຈະສ້າງໃຫ້ໃໝ່. ທ່ານຍັງສາມາດລະບຸເປັນ :memory: ເພື່ອໃຫ້ຖານຂໍ້ມູນຖືກເກັບໄວ້ໃນໜ່ວຍຄວາມຈຳຂອງລະບົບ – ເຊິ່ງການປ່ຽນແປງທັງໝົດຈະຖືກລຶບຖິ້ມເມື່ອ darktable ປິດລົງ.

      ທຸກຄັ້ງທີ່ darktable ເລີ່ມຕົ້ນ, ມັນຈະລັອກຖານຂໍ້ມູນໄວ້ສຳລັບຜູ້ໃຊ້ປັດຈຸບັນ. ໂດຍການຂຽນໝາຍເລກຂະບວນການ (PID) ລົງໃນໄຟລ໌ລັອກ <library file>.lock ໄວ້ຂ້າງໆຖານຂໍ້ມູນທີ່ລະບຸ. ຖ້າ darktable ພົບໄຟລ໌ລັອກທີ່ມີຢູ່ແລ້ວ, ມັນຈະຢຸດການເຮັດວຽກທັນທີ.

      --datadir <data directory>
      ກຳນົດໂຟນເດີທີ່ darktable ໃຊ້ຄົ້ນຫາຂໍ້ມູນການເຮັດວຽກ. ບ່ອນເກັບເລີ່ມຕົ້ນແມ່ນຂຶ້ນກັບການຕິດຕັ້ງຂອງທ່ານ. ບ່ອນເກັບປົກກະຕິແມ່ນ /opt/darktable/share/darktable/ ແລະ /usr/share/darktable/.
      --moduledir <module directory>
      darktable ມີໂຄງສ້າງແບບໂມດູນ ແລະ ຈັດລະບຽບໂມດູນເປັນໄລບຣາຣີລວມ (shared libraries) ເພື່ອໂຫລດໃນຂະນະເຮັດວຽກ. ຕົວເລືອກນີ້ບອກໃຫ້ darktable ຮູ້ວ່າຈະໄປຊອກຫາໄລບຣາຣີເຫຼົ່ານັ້ນຢູ່ໃສ. ບ່ອນເກັບປົກກະຕິແມ່ນ /opt/darktable/lib64/darktable/ ແລະ /usr/lib64/darktable/.
      --tmpdir <tmp directory>
      ກຳນົດບ່ອນທີ່ darktable ຄວນເກັບໄຟລ໌ຊົ່ວຄາວ. ຖ້າບໍ່ໄດ້ລະບຸຕົວເລືອກນີ້, darktable ຈະໃຊ້ຄ່າເລີ່ມຕົ້ນຂອງລະບົບ.
      --cachedir <cache directory>
      darktable keeps a cache of image thumbnails for fast image preview and precompiled OpenCL binaries for fast startup. Multiple thumbnail caches may exist in parallel – one for each library file. The default cache path is listed on the configuration directory page.
      --localedir <locale directory>
      Define where darktable can find its language-specific text strings. The default locale path is listed on the configuration directory page.
      --print-paths
      Print the resolved configdir, cachedir, tmpdir, datadir, moduledir, localedir and library paths for this install, honoring any of the overrides, then exit.
      --print-paths-as-flags
      Like --print-paths, but printed as a single line of –flag value pairs ready to insert into another invocation’s command line.
      --luacmd <ຄຳສັ່ງ lua>
      ຂໍ້ຄວາມທີ່ມີຄຳສັ່ງ lua ເພື່ອປະຕິບັດງານຫຼັງຈາກການເລີ່ມຕົ້ນ lua. ຄຳສັ່ງເຫຼົ່ານີ້ຈະຖືກລັນຫຼັງຈາກໄຟລ໌ “luarc” ຂອງທ່ານ.
      ຫາກບໍ່ໄດ້ມີການຕິດຕັ້ງ lua ມາໃນຕອນແປໂປຣແກຣມ (compiled-in), ຕົວເລືອກນີ້ຈະຖືກຍອມຮັບແຕ່ຈະບໍ່ເຮັດວຽກຫຍັງ.
      --noiseprofiles <noiseprofiles json file>
      ລະບຸໄຟລ໌ json ທີ່ມີໂປຣໄຟລ໌ສັນຍານລົບ (noise) ສະເພາະຂອງກ້ອງ. ບ່ອນເກັບປົກກະຕິແມ່ນ /opt/darktable/share/darktable/noiseprofile.json ແລະ /usr/share/darktable/noiseprofile.json.
      --conf <key>=<value>
      darktable ຮອງຮັບຊຸດພາຣາມິເຕີການກຳນົດຄ່າຈຳນວນຫຼາຍທີ່ຜູ້ໃຊ້ກຳນົດໄວ້ໃນໄຟລ໌ darktablerc, ເຊິ່ງຕັ້ງຢູ່ໃນໂຟນເດີທີ່ລະບຸໂດຍ --configdir ຫຼື ໂຟນເດີກຳນົດຄ່າ ເລີ່ມຕົ້ນ. ເຈົ້າສາມາດຂຽນທັບການຕັ້ງຄ່າແຕ່ລະຢ່າງຊົ່ວຄາວໃນ command line ດ້ວຍຕົວເລືອກນີ້ – ການຕັ້ງຄ່າເຫຼົ່ານີ້ຈະບໍ່ຖືກບັນທຶກໄວ້ໃນ darktablerc ເມື່ອອອກຈາກໂປຣແກຣມ.
      -t <num openmp threads>
      ຈຳກັດຈຳນວນເທຣດ (threads) ຂອງ openmp ທີ່ຈະໃຊ້ໃນສ່ວນການປະມວນຜົນແບບຂະໜານ.
      --dump-pfm MODULE_A,MODULE_B, --dump-pipe MODULE_A,MODULE_B, --dumpdir DIR
      ຕົວເລືອກເຫຼົ່ານີ້ມີໄວ້ເພື່ອແກ້ໄຂຂໍ້ຜິດພາດໃນຂະບວນການປະມວນຜົນພາຍໃນຂອງ darktable. ຕົວຢ່າງ, ຖ້າເອີ້ນໃຊ້ດ້ວຍ --dump-pfm demosaic, darktable ຈະສົ່ງອອກຂໍ້ມູນຂາເຂົ້າ ແລະ ຂາອອກຂອງໂມດູນ demosaic ເປັນໄຟລ໌ pfm. ໂດຍປົກກະຕິແລ້ວ ບ່ອນເກັບໄຟລ໌ເຫຼົ່ານີ້ຈະຖືກກຳນົດໂດຍລະບົບປະຕິບັດການ, ແຕ່ທ່ານສາມາດກຳນົດເອງໄດ້ຜ່ານຕົວເລືອກ --dumpdir.
